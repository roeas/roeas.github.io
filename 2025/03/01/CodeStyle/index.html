代码规范

本文最后更新于 2025-03-10T02:49:54+08:00

一些个人习惯而已。

头文件

  • 分四部分依次排列
    1. cpp 文件对应的头文件
    2. 解决方案内源码可见的头文件
    3. 第三方库的头文件
    4. 标准库头文件
  • 第三方库用 <> 自己的头文件用 “”
  • 按字典序排序
  • 清理不必要的头文件
  • C++ 标准库头文件不带扩展名，C 头文件带 .h，C++ 程序中尽量用 C++ 头文件

大括号

  • 不要省略单行代码的大括号
  • 命名空间内容不缩进

命名

  • 函数大写驼峰
  • 变量小写驼峰
  • 使用 int *p 而非 int* p
  • 使用 int &r 而非 int& r
  • 成员变量 - m_
  • 指针 - p_
  • local 静态变量 - s_，静态成员变量不加，因为 T::m_ 的用法足以说明该变量的类型
  • 编译期常量 - 全大写
  • 数组等容器中的元素数量 - number(num)
  • 累计值 - count(cnt)
  • 字节数 - size
  • 字符串长度 - length(len)

注释

  • // 前后加空格
  • 多行注释每行开头加 *
  • 首字母大写
  • 除非是长篇的描述，否则不加句号
  • 使用 does not 而非 doesn't
  • 公式之类非英文的部分用 `` 括起来
  • // TODO: Do something
  • 命名空间右大括号后跟注释

类型

  • 可以使用 int 和 char
  • 使用 int16_t 而非 short，使用 uint64_t 而非 unsigned long long
  • 使用 true 和 false 而非 0 和 1 来表示 bool
  • 涉及位运算时使用无符号整数
  • 避免对无符号整数进行可能为负的运算
  • 与第三方库交互时优先遵循该库的返回类型

其他

  • 4 空格缩进
  • 前向声明
  • final
  • 成员可访问级别
  • 三五法则
    • 如果你需要自定义拷贝构造函数、拷贝赋值运算符或析构函数中的任何一个，那么你可能需要自定义所有这三个函数。
    • 如果你需要自定义移动构造函数或移动赋值运算符，那么你可能需要自定义所有五个函数。
  • 提供参数为右值的重载函数，传值就完事了，实现内再 move
  • 将参数作为索引时用 const T&，当 sizeof(T) < 8 时不用 &
  • 用 const 修饰 this 指针
  • 用 string_view 代替 string
  • 尽量用 assert 代替 if check log，C++ 最好的错误检查就是崩在一个合理的地方
  • 用 std::tuple 和结构化绑定代替一些过分临时的结构体
  • 怎么处理编译期可确定的映射关系
    • constexpr array（键为或者能够转换为非重复的整数下标）
    • constexpr 函数 / Lambda 里的 switch-case
